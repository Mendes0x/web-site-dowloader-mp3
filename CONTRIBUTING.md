# Contributing

Contributions are welcome. Prefer useful changes with clear rationale over activity created only to collect GitHub badges.

1. Open an issue or describe the bug.
2. Create a feature branch.
3. Make a focused change and add offline tests.
4. Run `npm ci`, `npm run check` and confirm the UI on mobile.
5. Open a pull request with test results and screenshots where appropriate.
6. Respond to review feedback.

Good first tasks: accessibility improvements, translations, improved yt-dlp diagnostics, safe disk cleanup, better persistent history, additional queue tests.

Never publish credentials, DRM circumvention methods, unauthorized media, API keys or personal recordings in issues, tests or commits. Keep the server loopback-only unless a complete authorization and threat model is developed.
